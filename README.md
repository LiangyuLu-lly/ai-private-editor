# AI 私密编辑

一个 Chromium Manifest V3 本地隐私辅助扩展。在豆包、DeepSeek、元宝、ChatGPT、Claude、Gemini、Kimi、通义千问和文心一言的已验证网页聊天输入框中，扩展会在浏览器本地处理正常发送和纯文本粘贴：普通替换模式把可替换的结构化敏感信息变成令牌文本再交给网站；高风险凭证、严格模式或类别策略命中会先提示用户确认，确认类命中默认先提供“匿名化发送”，原文发送仅适用于本次。用户可在本地白名单中明确放行认可的精确值。

当前版本为 `0.4.4` 本地原型（构建标识 `private-composer-r9-send-gate-2026-09-07.1`），不含后端、账号、遥测、远程规则下载或网络代理。

**想动手把每个功能过一遍**：看 [TRY-IT.md](TRY-IT.md)。从装载到逐项验收的清单，每一项都写了怎么做、该看到什么、看不到说明什么；其中涉及检测行为的断言都在出货产物上实测过。发布与打包流程见 [RELEASE.md](RELEASE.md)，上架粘贴文案见 [STORE-LISTING.md](STORE-LISTING.md)，商业化清单与企业免责提纲见 [COMMERCIAL.md](COMMERCIAL.md)。

## 当前范围

- 支持 `www.doubao.com`、`doubao.com`、`chat.deepseek.com`、`yuanbao.tencent.com`、`chatgpt.com`、`claude.ai`、`gemini.google.com`、`www.kimi.com`、`www.qianwen.com`、`yiyan.baidu.com` 和 `wenxin.baidu.com` 的聊天页；DeepSeek `/sign_in`、Claude 的登录/登出页面不支持。只有当前页面的编辑器通过健康检查时，扩展才接管；发送控件此刻是否存在、是否可用不参与这个判断，而是在真实发送那一刻单独判断（所有站点在输入框为空时都会禁用或不渲染发送按钮，那是空闲状态）。
- 元宝 Beta 只识别当前已取证的唯一 Quill 编辑器和唯一精确发送锚点。公开未登录页面的发送锚点始终置灰，扩展仍会把它视为结构完好（置灰是空闲状态，不是适配失效），但该状态下发不出消息，任何发送动作都会停在“请手动发送”而不会被代为点击；认证后点击、Enter、严格模式和输入法路径仍需在用户自有账号中以合成文本完成手工验收后，才能视为已完成发布级验证。
- ChatGPT 只识别当前精确的 Composer 文本框和发送按钮；Claude 只识别当前唯一的 ProseMirror 编辑器和发送按钮；Gemini 只识别当前 Quill 编辑器及其同一 `text-input-field` 容器内的发送按钮。Gemini 空输入时不渲染发送按钮，ChatGPT 则把它换成语音按钮；这两种空闲状态都不会被判为适配失效，空白页面上仍显示 `ON`。页面结构不符合这些条件时，扩展完全原生放行。Claude 的登录态真实发送路径尚需用户自有账号手工验收。
- Kimi 只识别 `.chat-input` 内唯一的聊天编辑器和发送容器；通义千问以已取证的 `data-testid="chat-input-content-measure"` 为锚点，仅在固定两层祖先的同一输入组件内识别唯一“发送消息”按钮；文心一言只识别 `#chat-textarea` 与同一输入区中的 `.ci-submit-button`。这三站已完成公开页面结构取证，登录态点击、Enter、输入法和附件路径仍需使用合成文本手工验收。
- 高置信 API 密钥、访问令牌、私钥和连接字符串，以及“密码/密钥/令牌/CVV 等明确字段标签 + 冒号”的值，会在可识别发送动作前阻断当前事件并进入确认；全角字符、兼容连字符、零宽与双向格式控制字符、特殊空格会先在本地建立位置映射后检测。超长凭证会完整匿名化，但原值不会保存在会话令牌映射中。
- 手机号、邮箱、有效中国居民身份证号、Luhn 有效卡号、有效统一社会信用代码、IPv4、本机路径、标准 MAC 和明确生日字段会替换为令牌，例如 `[[PHONE_001]]`；同一页面文档内，相同的规范化值跨多次发送会复用同一令牌。聊天语境中的 62 开头 16 位银联号、带身份证语境但校验位不完整的号码、对公/收款/结算账户和已知网盘分享链接会作为需确认候选处理。回环地址（`127.0.0.0/8`）与 `0.0.0.0`、`255.255.255.255` 不携带可识别信息，不会被替换；内网私有地址仍会替换，因为内网地址本身属于敏感资产。
- 两种检测范围都会处理结构化格式、明确“字段标签 + 分隔符 + 值”以及有限高信号中文上下文；后两类一律走发送前确认，不会静默改写。分隔符支持 `:`、`：`、`=`、`是`、`为`、`叫`。平衡范围还可叠加用户明确开启的本地统计或本地神经模型；它们不会连接远程模型，也不构成任意自由文本的完整语义理解。
- 用户可在浏览器工具栏的“自定义敏感词”中按个人、工作、项目、其他四个固定分组保存需要匿名化的字面量词条；普通替换模式命中后会替换为 `[[CUSTOM_001]]` 等令牌。
- 工具栏弹窗中的“私密编辑器”会在扩展侧栏打开独立草稿区。草稿先在扩展页面内存中检查，再把本地生成的出站文本填入当前已验证网页；它不会自动点击网页发送。检查到“发送前确认”策略时，按钮会明确变为“确认匿名化填入”；“始终阻止”策略不会提供填入动作。侧栏会绑定站点、标签页和当前页面实例，填入前再次核验，切换标签页或页面刷新后旧预览不可写入。为避免白名单值原样进入网页，侧栏不使用全局或站点白名单放行。若未命中规则，出站文本会与草稿相同并明确提示，仍应由用户审阅后决定是否填入。
- 用户可在弹窗的“白名单”视图保存认可的精确值，并指定为全局或单站点范围；站点范围需要明确确认并默认 1 天后失效。密码、密钥、令牌、私钥和连接串不会被全局白名单静默放行；这类值需要当前页面会话允许，或尚未到期的明确站点范围放行。
- 用户可在“类别策略”中把每个敏感类别设为自动匿名化、发送前确认或始终阻止；默认策略沿用内置规则。始终阻止可通过调整策略或白名单解除。
- 严格模式只在已验证的发送路径上生效：命中任一可替换规则（含明确标签字段）或自定义词时先弹出确认；默认匿名化发送，取消不发送，明确选择“仅本次发送原文”才按原文重放一次。
- 在已验证编辑器中粘贴纯文本时，扩展在文本进入网页前走与发送相同的本地检测。启用本地神经模型时，未完成复核的剪贴板文本不会静默插入；用户只能取消粘贴，或明确选择“仅本次按原文粘贴”。富文本粘贴保持网页原有路径，避免破坏格式或误接管未知编辑器。
- 可在“保护”视图选择保守或平衡检测、令牌/部分掩码/类型占位三种替换方式，以及附件提示策略。类型占位不会生成真实身份证、手机号或账号。
- 启用“回复令牌查看”后，已发送令牌若再次出现在当前页面上，可由用户显式点按临时查看原值；查看浮层属于扩展页面级宿主，避免被消息气泡裁剪，5 秒后自动清除。定位方式不依赖站点私有结构：ChatGPT 用已取证的两类助手角色标记，其余站点按扩展自己生成的令牌定位，且只装饰经本页面会话确认过的令牌。因此用户自己已发出的消息气泡里的令牌同样可点（那本来就是用户输入的原文）。输入框内的令牌一律不装饰，避免破坏正在写的草稿。悬停扩展图标可看到“未识别回复区域 / 暂无令牌 / 已绑定令牌”的本地诊断。
- 附件策略只在站点声明了输入区局部附件节点时检测当前输入区是否存在已附加文件，支持不提示、提示后继续、发送前确认或“阻止并允许单次继续”；从不读取附件名称、路径、类型或附件内容。未声明能力的站点在“发送前确认”或“阻止”设置下会暂停本次发送并要求一次性放行，而不是把未知状态伪装成“无附件”。
- 支持已验证发送按钮、正常 Enter 和表单提交；Shift+Enter、输入法组合状态和未知页面路径不会被当作发送手势。
- 站点适配健康检查失败时，扩展不读取该次发送的词库快照、不检测草稿、不改写、不阻止、不重放，也不宣称该页面已受保护；页面会提示“敏感文本可能按原文发送”，网页仍按原有路径处理。

## 工具栏保护状态

在已支持网页中，工具栏图标按标签页显示当前适配状态；将鼠标悬停在图标上可查看完整说明。

- `ON`：当前页面的已知编辑器已通过健康检查，粘贴拦截、输入时检查与发送拦截都已挂上。本次正常发送会进入本地脱敏链路，但这不表示规则能识别所有敏感信息，也不表示网页从未接触输入原文。发送按钮此刻是否存在或可用不影响这个徽标——所有站点在输入框为空时都会禁用或不渲染发送按钮，那是空闲状态；能不能真的替你按下去由发送那一刻单独判断，不能时会提示手动发送。
- `!`：当前页面未通过健康检查，扩展不会接管该次发送；网页按原有路径处理。原因是页面结构变化：找不到输入框、输入区结构与预期不符，或者**输入框里已经有字却仍然找不到发送按钮**（最后一种说明发送按钮的选择器已失效，此时点击那条路不会被接管）。
- 无徽标：正在检查，或当前标签页不在扩展支持范围。新导航开始时会清除上一页面的状态，避免 `ON` 跨页面残留。

状态通道只把固定站点标识、`checking`、`protected`、`unverified` 状态，以及启用回复查看时的“回复容器数 / 已绑定令牌数”交给扩展自身的本地 service worker；不传递草稿、命中类别、令牌文本或聊天记录。为避免旧页面的延迟状态覆盖新页面，worker 仅在内存中暂存浏览器提供的文档 ID，并在标签页关闭时清除；不写入扩展存储。它不读取标签页 URL、标题、Cookie 或页面文本，也不请求 `tabs` 权限。

不读取或脱敏附件、图片、音频、截图内容；不扫描已有聊天记录；不保证识别没有高信号上下文的姓名、地址或任意业务语义；也不能保证覆盖规则外的凭证格式。

## 发送前本地处理

在已适配网页输入框正常输入
-> 点击发送或按站点发送快捷键
-> 扩展先确认已适配的编辑器和发送控件，再在浏览器本地检查
-> 本地神经模式先停止事件，等待最终草稿完成本地语义复核
-> 普通替换模式命中替换规则时自动发送令牌文本
-> 严格模式或命中高风险凭证时弹出确认，默认选择匿名化发送

- 未命中规则：扩展不改写输入框、不显示提示，网站按原有发送路径处理文本。
- 命中替换规则且使用普通替换模式：原始发送事件被阻止，输入框改为令牌文本；站点发送控件可用时仅重放一次。控件在重放前变得不可用时，令牌文本会保留并提示手动发送。
- 严格模式命中替换规则：原始事件先被阻止，原文保留在输入框；默认“匿名化发送”会把令牌文本写回并只重放一次已验证发送控件；也可取消，或明确选择“仅本次发送原文”。
- 命中高风险凭证：原始事件先被阻止，原文保留在输入框；确认框默认匿名化发送，原文发送必须通过单独的风险按钮明确选择。
- 本地神经模式缓存未命中、复核失败，或内容脚本与 service worker 任一侧超过 15 秒仍无结果：原始事件先被阻止，并给出与模型不可用相同的选择。挂起的模型不会让发送一直停住且无反馈。扩展不会把空缓存当成“无敏感信息”。用户可取消，或明确选择“仅本次按原文发送”；该选择不加入白名单、不建立会话放行。
- 确认弹窗只显示敏感类别和数量，不显示完整原文；一次性原文确认不会自动加入白名单，也不会创建会话放行。选择“本会话允许”才会把本次发现的精确值加入当前页面内存放行集合。等待确认期间页面结构或草稿内容发生变化时不重放，原文保留并提示重新操作。
- 适配健康检查失败或站点未适配：扩展不接管该次交互，不能把它视为已保护。内容脚本可能仍为已注册域名预加载本地词库配置，但不会读取该次草稿或在该次发送中读取词库快照。

## 粘贴前本地处理

- 仅处理指向已验证聊天编辑器的纯文本粘贴。启用本地神经模型时，粘贴与发送共用同一套复核门控：未复核完成不会把剪贴板原文静默插入；对话框标题为“本地语义复核未完成”，只有“取消粘贴”和“仅本次按原文粘贴”。命中可替换规则时，浏览器默认粘贴会被阻止，令牌文本在本地插入编辑器后再交给网页。
- 高风险、严格模式或“发送前确认”类别会显示同一类确认；默认“匿名化粘贴”先插入令牌，取消不粘贴，明确选择原文按钮才本次插入原文。“本会话允许”只存在当前页面内存，刷新或关闭标签页即失效。
- 富文本、附件、图片和未验证编辑器不被拦截，网页按其原有路径处理。这是边界，不代表其内容已受到保护；未验证附件节点尤其不能被理解为已扫描。

在一个仍存活的页面文档内，扩展会在内容脚本内存中维护“规范化敏感值 -> 令牌”的映射。因此同一手机号、忽略大小写且兼容连字符后相同的邮箱、相同的明确标签值，或相同的自定义词条，在后续消息中仍会使用原令牌；新的同类值才获得下一个编号。映射不写入网页 DOM、`chrome.storage`、service worker 或网络。用户可在“保护”视图清除所有已打开受支持页面的会话映射和本会话允许；刷新、关闭标签页或重载扩展后也会重新开始编号。超长凭证只保留不可还原的短标记，不可通过回复查看恢复原值。

## 自定义敏感词

点击浏览器工具栏中的“AI 私密编辑”图标，在“自定义敏感词”弹窗中添加需要匿名化的字面量。

- 词条、分组和严格模式仅保存在此浏览器本地的 `chrome.storage.local` 中，不会同步或上传；可删除单条词，或确认后清空全部。
- 输入框每行一个词条，可一次粘贴多行；当前选择的个人、工作、项目或其他分组会应用到整批。任一有效行重复、超长或会使总数超过上限时，整批不会保存。
- 每个词条最长 120 个字符，最多保存 100 个；按插入顺序保存，重复词条会被拒绝。搜索和分组筛选只影响弹窗显示，不影响实际脱敏范围。
- 匹配是区分大小写的字面量精确匹配，不支持正则表达式、通配符或语义识别。
- 词库正在加载或读取失败时，扩展会停止已识别的非空发送动作，不会把它当作空词库放行；原文会留在网页输入框。

## 白名单

在工具栏弹窗切换到“白名单”视图，添加需要按原文发送的精确值。白名单与自定义敏感词分开管理，仍只保存在 `chrome.storage.local`。

- 区分大小写，按字面量精确匹配；手机号空格/连字符、邮箱大小写等内置规范化仍会用于候选比较。
- 白名单优先于内置规则和自定义敏感词；普通值命中后不替换、不进入严格模式确认，也不产生检测 finding。
- API 密钥、访问令牌、私钥、连接串和明确凭证字段不会被全局白名单放行；站点范围高风险值必须仍在有效期内，本会话允许只存在当前页面内存。
- 全局白名单可长期保存；指定网站白名单会要求确认，并默认 1 天有效。过期项在发送时自动失效，可逐条删除或确认后清空。
- “仍发送原文”只对当前一次发送有效，不会自动写入白名单。
- 确认框中的“本会话允许”也不会写入白名单；它仅让当前页面内存中的相同规范化值在本会话内按原文继续发送或粘贴。

## 类别策略

在工具栏弹窗的“策略”视图中，可分别设置 API 密钥、手机号、明确标签字段等类别。

- 默认：保留内置行为，高风险类别先确认，其余可替换类别自动匿名化。
- 自动匿名化：即使该类别默认需要确认，也优先发送令牌文本。
- 发送前确认：保留原文，用户可取消、仅本次发送原文，或本会话允许。
- 始终阻止：停止本次发送或粘贴，不提供原文绕过按钮；通过白名单或修改该类别策略后才能继续。

## 保护设置

在工具栏弹窗的“保护”视图中管理以下本地选项：

- 检测范围：默认“保守”处理结构化格式、明确字段和有限高信号上下文；其中上下文候选均需确认。“平衡”可额外使用已启用的本地统计或神经模型，适合希望降低自由表达漏检风险的场景，但可能增加确认提示。
- 替换方式：令牌会保留会话级对应关系；部分掩码只保留格式所需的少量字符；类型占位使用诸如 `<联系人-001>`、`<邮箱-001>` 的非真实占位，不生成可用身份或凭证。
- 回复令牌查看：仅令牌模式可启用；原值不写入网页文本节点、扩展存储或网络，刷新、关闭标签页或重载扩展后即不可恢复。
- 附件发送：声明能力的适配器会在已验证输入区内按附件元素提示、要求确认或先阻止；“阻止并允许单次继续”会停止本次动作，只有用户明确选择一次性继续后才走网页原生附件路径。未声明能力的站点在确认/阻止模式也会暂停并标明“无法核验附件状态”。扩展不读取附件内容，且页面结构未验证时不接管。
- 语义审查：在“平衡”检测下可启用“本地统计模型”或“本地神经模型”。统计模型为冻结的本地字符 n-gram 附加评分；神经模型为随扩展打包的 ONNX INT8 学生，只输出姓名、地址和账号别名候选。网页输入时，神经推理在输入停顿后于扩展自己的 offscreen 文档预热；点击发送或纯文本粘贴后会停止原始事件，并等待同一份最终草稿完成本地复核，再进入规则与模型合并检测。未命中缓存、超过 5,000 字、模型不可用，或内容脚本 / service worker 任一侧超过 15 秒仍无结果时，不会静默按规则发送或插入，而是提示取消或“仅本次按原文”。运行时清单缺少 `threshold`、`max_length`、`stride` 或 `labels` 时会中止加载，不会静默套用默认值。模型加载失败会有限次重试（最多 3 次），而不是在该页面文档生命周期内永久禁用。私密编辑器也等待同一模型结果。所有模型候选一律要求确认，不上传用户草稿，也不用于训练。

## 本地文件扫描

在“保护”视图点击“本地文件扫描”，再主动选择单个文件。扫描页不会把文件通过扩展消息、存储、审计或网络传出；只有发现已识别敏感项时才提供处理副本下载。

- 支持 TXT、Markdown、CSV、JSON、YAML、XML、日志和常见源码的文本扫描；DOCX/XLSX 提取文档 XML、单元格、公式、批注、超链接，以及 `docProps` 文档属性（作者、最后修改者）和 `customXml` 自定义数据后生成脱敏文本副本；PDF 只扫描最多 20 页的文本层，不改写 PDF，且无论提取到多少文字都标为“部分扫描”。
- PNG、JPEG 和 WebP 使用扩展内置的中文/英文 OCR 资源在本地识别；会处理同一行被拆开的邮箱、号码和中文字符词框。已识别敏感词框会生成实心打码 PNG。以下两种情况会保留识别结果但不生成打码副本，并提示手动处理原图：图片带有非正立的 EXIF 方向（浏览器解码必定应用该方向，而词框坐标处于文件头声明的未定向坐标系，遮挡会落在错误位置），或识别结果因超出词数上限而被截断（副本只能遮住前一部分）。低置信 OCR、无文本层 PDF、PDF 页数上限，以及 Office 中未提取的内嵌媒体或对象（图片、OLE 对象、缩略图等）会显示“部分扫描”，不能视为安全。
- 上限为单文件 10 MiB、可提取文本 2 MiB、图片 12 MP、单边 16,384 px、PDF 20 页。Office 文件会在解压前检查 ZIP 路径、加密标记、条目数、重名条目、压缩比、未压缩体积，以及单个待提取 XML 条目的压缩数据量（512 KiB）。前几项依据压缩包自身声明的数值，声明可以造假；压缩数据量限制用于约束最坏解压体积，但仍不能完全排除恶意压缩包耗尽扫描页内存。
- 扫描器不继承网页发送用的白名单或类别策略，避免已放行的值进入文件处理副本；仍使用用户自定义词、检测档位和可选本地语义审查。由于类别策略不参与文件扫描，“需复核”只由本地语义候选触发。任何“部分扫描”的处理副本都会保持禁用，直到用户在本地扫描页明确确认当前识别结果或扫描范围；图片的需复核结果不生成打码副本。
- 扫描器是独立预处理工具，不能保证阻止网站已经发起的上传。请先扫描，再手动上传处理副本；不要在目标聊天网页中先选择原件。

## 本地审计

“审计”视图默认关闭。开启后，本地最多保留 100 条记录，每条仅有站点、发送或粘贴、结果（已匿名化/已确认原文/已取消/已阻止）和敏感类别数量。

- 不记录原文、令牌、字段标签、聊天标题或聊天记录。
- 审计记录只保存在 `chrome.storage.local`，可随时在弹窗单独清空；关闭开关后不再新增记录，已有记录不会自动上传或同步。

## 配置迁移

“迁移”视图可生成或导入本地配置 JSON。默认导出自定义词、类别策略、审计开关和保护设置，不含白名单、审计记录或会话令牌；只有主动勾选并确认后才包含白名单。

- 导出文件可能包含你自己定义的敏感业务字面量和放行值，不应分享给他人。
- 导入会先严格校验 JSON 和版本。导入方式可选“替换现有配置”（确认后原子替换全部配置）或“合并白名单”（白名单与现有条目求并集，同值同站点保留较晚到期时间，不删除已有放行值；自定义词等其余项仍按导入文件写入）。校验失败或取消替换时不会改动已有配置。

## 严格模式

弹窗中的“严格模式”默认关闭。开启后，只有已验证发送路径上的可替换命中会弹出确认；无匹配文本仍按网站原有路径发送。高风险密钥、访问令牌、私钥和连接字符串也会弹出确认，默认可匿名化发送，用户可以取消或明确选择只对本次发送原文。严格模式不扩大站点范围，也不会在未适配或适配健康检查失败的页面拦截任意按钮。

## 数据边界

扩展本身不上传、不调用后端，也不拦截网页网络请求。它不读取 Cookie、会话令牌或网页私有 API，不持久化聊天草稿、完整检测结果或会话历史。启用本地神经模型时，输入草稿会在扩展内部经 `content script -> service worker -> offscreen document` 进行瞬时本地推理，结果返回当前内容脚本的精确草稿缓存；不写入 `chrome.storage`、IndexedDB 或网络。用户主动添加的自定义敏感词、固定分组、严格模式、白名单、类别策略、检测范围、替换方式、回复令牌查看开关和附件策略会保存在 `chrome.storage.local`，以便关闭弹窗、刷新页面或重启浏览器后继续生效；该配置不使用 Chrome 同步，也不会上传。用户主动启用本地审计后，另有最多 100 条只含类别数量的摘要记录保存在同一处。扫描页不写入审计或扩展存储，关闭、清除或替换文件后会丢弃扫描结果和处理副本对象。会话清除操作只写入一个不含原文的随机信号。普通替换模式的会话令牌映射是例外的短暂内存状态：它保存当前页面文档中已匹配值的规范化形式与令牌对应关系，用于连续消息一致性；不会离开内容脚本内存，也不会跨刷新、关闭标签页、扩展重载或用户清除映射持久化。

但“本地处理”不等于目标网站从未看到原文：用户直接键入网页聊天框的原文会存在于目标网页 DOM，页面脚本可能读取它。此扩展只降低通过可识别正常发送动作把结构化敏感值提交给聊天服务的风险，不能防护恶意网页脚本、其他浏览器扩展、操作系统级记录器、站点草稿功能或规则漏检。

完整说明见 [PRIVACY.md](PRIVACY.md)。

## 本地运行

```powershell
npm install
npm test
npm run test:browser
npm run build
```

`npm test` 在 jsdom 中运行，覆盖检测、映射、还原与界面逻辑。`npm run test:browser` 运行图片几何回归，并尝试验证 offscreen ONNX 路径；当 Chrome 阻止 CDP 临时装载的扩展页时，神经用例会明确跳过，不能代替在用户手动装载的扩展中运行“本地模型自检”。该命令用 `playwright-core` 驱动系统浏览器，不下载浏览器。评测脚本（`eval-with-neural`、`eval-rules`、`eval-blind-probe`）会把无法映射到评测标签的检测种类写入输出目录的 `dropped-kinds.json`，不再静默丢弃。

构建后的可加载扩展位于 `dist/`。请在扩展管理页加载并重新加载刚构建的 `dist/` 目录；工作区中已有的旧压缩包不是本次构建的权威发行物。

1. 在 Chrome 打开 `chrome://extensions`，或在 Edge 打开 `edge://extensions`。
2. 开启“开发者模式”。
3. 选择“加载已解压的扩展程序”。
4. 选择本项目的 `dist` 文件夹。
5. 每次重新构建后，在扩展管理页点击“重新加载”，再刷新已经打开的受支持聊天页。若页面提示“保护规则已更新”，说明该标签页仍在运行旧内容脚本；刷新后再发送，等待图标恢复 `ON`。
6. 如需自定义词条、白名单、类别策略、严格模式、本地审计或配置迁移，点击浏览器工具栏中的“AI 私密编辑”图标，在对应视图中管理本地配置。
7. 在支持网页输入一段无害测试文本并等待发送控件可用；图标显示 `ON` 后，正常输入并发送。日常发送无需打开弹窗。

## 手工验收

在每个可登录的受支持站点分别检查点击发送、正常 Enter 和纯文本粘贴：

```text
替换：请联系 13800138000，邮箱 li@example.com。
标签替换：对接人：测试甲，家庭住址：北京市海淀区测试路12号，微信号：sample_wechat_42。
信用代码替换：统一社会信用代码：91110108MA01K12342。
自定义替换：请整理青岚项目的测试安排。
严格确认：开启严格模式后，请整理青岚项目的测试安排；先取消确认，再重复发送并确认原文发送。
阻断：sk-proj-abcdefghijklmnopqrstuvwxyz1234567890ABCDEFGHIJ
字段阻断：数据库密码：synthetic-test-password
无匹配：请把这段无害测试文本改短。
```

在工具栏弹窗选择“项目”并添加 `青岚项目` 后，自定义替换样例应只提交 `[[CUSTOM_001]]`；内置替换样例应只提交 `[[PHONE_001]]`、`[[EMAIL_001]]` 等令牌。开启严格模式后，严格确认样例第一次取消应保留原文且不创建新消息，第二次确认后应只创建一条原文消息；高风险凭证也应遵循同样的一次性确认；无匹配样例应保持网站原有行为。本地神经模式下，粘贴一段规则不会命中的文本时，未复核完成不得先把原文插入输入框；只能取消或明确选择“仅本次按原文粘贴”。复核超过约 15 秒无结果时，应出现与模型不可用相同的确认，而不是发送或粘贴一直无反馈。另行确认 Shift+Enter 仅换行、输入法候选确认不提前发送、缺少可识别编辑器或发送控件的页面不显示保护成功提示，且 DeepSeek 登录页不被写入。

在“保护”视图另行验收：选择“平衡”后发送 `项目负责人叫测试甲，请把样品寄送到北京市海淀区测试路12号；我的微信 ID 是 sample_wechat_42。`，应只提交对应的人员、地址和账号令牌；“保守”也会把高信号上下文作为确认候选，但不会启用模型补充。全角混淆测试 `请联系 １３８​００１３‍８０００。` 仍应提交 `[[PHONE_001]]`。将替换方式改为“类型占位”后，手机号应显示为 `<手机号-001>` 而非真实号码；改回“令牌”并开启“回复令牌查看”后，在同一页面发送 `请联系 13800138000。`，若站点助手回复包含 `[[PHONE_001]]`，点按它只能在短暂浮层中显示原值，网页正文和刷新后的页面均不应出现原值；若无反应，悬停扩展图标查看回复容器诊断。选择“附件发送：发送前确认”或“阻止并允许单次继续”后，未声明附件能力的站点也必须出现“无法核验附件状态”的本次确认，而不是静默发送。

在豆包或已登录 DeepSeek 的新对话中，先输入 `状态检查测试` 并等待图标显示 `ON`；删除文本导致发送控件再次不可用时，图标应变为 `!`。刷新页面或在站内切换新对话后，旧状态应先清除，再依据新页面 DOM 显示 `ON`、`!` 或无徽标。只使用合成测试文本。

另做会话稳定令牌测试：先发送 `请联系 13800138000。`，应得到 `[[PHONE_001]]`；随后发送 `请先联系 13900139000，再联系 13800138000。`，应分别得到 `[[PHONE_002]]` 和 `[[PHONE_001]]`。在“保护”视图点击“清除已打开页面的会话映射”后，再发送任一号码应重新从 `[[PHONE_001]]` 开始。刷新页面后也应重新从 `[[PHONE_001]]` 开始。开启严格模式并发送同一号码，取消确认时不会分配令牌，确认原文发送也不会写入令牌映射。

元宝目前只完成公开未登录页面的 DOM 取证：该状态必须不拦截。发布前，在用户自有元宝账号中仅使用上述合成文本，分别验证发送锚点点击、正常 Enter、严格阻断、Shift+Enter 和中文输入法组合输入；不得用真实个人信息、密钥或业务数据作测试。

ChatGPT 当前适配应在登录态新对话中以合成文本验证一次点击发送、Enter、纯文本粘贴、严格确认和白名单。Claude 在本环境未取得登录态真实输入框，因此必须在用户自有账号中以相同合成文本验证；Gemini 先在空输入状态确认 `!`，再输入合成文本并等待发送按钮出现、图标变为 `ON`，然后验证点击、Enter、纯文本粘贴、严格确认和白名单。Kimi、通义千问和文心一言还应分别验证点击、Enter、Shift+Enter、输入法组合输入和附件确认。若图标为 `!`，不要把该页面视为已保护，应收集当前 DOM 取证后再调整选择器。

ChatGPT 当前登录态还观察到 `#mobile-composer-prompt` 与 `form.wm-composer-composer` 组件；适配器同时保留旧版 ProseMirror 结构，两个布局同时出现时会停止接管。

## 权限

清单请求 `storage` 和 `sidePanel` 两项扩展权限，需要 Chromium 116+；`storage` 只用于 `chrome.storage.local` 中的本地配置和可选审计摘要，`sidePanel` 只用于扩展自有的私密草稿界面。内容脚本主机范围仅限 11 个精确地址模式（豆包两个域名、DeepSeek、元宝、ChatGPT、Claude、Gemini、Kimi、通义千问和文心一言两个域名）。本地 service worker 更新工具栏状态，并且只转发来自扩展侧栏的 `PING` 或含已检查出站文本的填入请求；每个已打开网页文档生成一个不含原文的随机绑定键，填入请求须同时匹配站点、标签页和绑定键，避免同站标签页切换或导航后误写。它不接收草稿字段、不读取标签页 URL、标题或页面内容。它不请求 `<all_urls>`、`tabs`、`webRequest`、`declarativeNetRequest`、剪贴板或原生消息权限，也不使用 `chrome.storage.sync`。

## 已知限制

- 规则、校验算法和有限中文上下文可能漏检或误检；平衡检测并不等同于本地大模型语义理解，未命中内容会按原网站路径发送。确认类命中也不等于绝对隔离，因为原文先由网页输入框接收。
- 私密编辑器仅改善用户在侧栏中输入的纯文本路径：侧栏本身仍在浏览器扩展页面内存中暂存草稿，规则漏检时出站文本仍可能包含原文；它不处理附件、图片、语音、网页已存在的草稿或用户后来直接在网页输入框追加的内容。
- 网站前端结构更新可能导致适配健康检查失败。此时扩展会走网页原生路径并且不宣称该页面受保护；已开始的替换路径无法重放时，扩展保留令牌文本并提示手动发送，不构造网络请求或反复重试。
- 当前 R9 已在真实 Chrome 153 中通过扩展装载、offscreen/WASM、跨度一致性和空草稿自检；Edge 仍需单独回归。元宝 Beta、Claude、Kimi、通义千问和文心一言仍缺少用户自有账号下的认证发送路径验收。ChatGPT、Claude、Gemini 或国内站点的前端结构变化也可能使精确选择器失效。
- 发布到 Chrome Web Store 或 Edge Add-ons 前，发行方必须将 `PRIVACY.md` 托管为公开可访问的隐私政策 URL，并补充真实的发行主体和联系渠道。
